# از این‌جا شروع کن — دست‌به‌دست کردن «مدرسهٔ هدایت»

> این سند برای همکار تازه است، آدم یا Claude. اگر فقط یک چیز می‌خوانی، همین باشد.
> نسخه را از «سرگذشت نسخه‌ها» (`CHANGELOG.md`) ببین؛ این سند با هر انتشار در بایگانی بارگذار به‌روز می‌شود.

## مدرسهٔ هدایت چیست

سامانهٔ یادگیری و همراهی امامان جماعت، شریکة‌الامام‌ها (همسران امام)، دستیاران امام و هسته‌های نوجوان و جوان مسجد. کاربر با شماره وارد می‌شود، نقش و مسجدش را می‌گوید و «مسیر اصلی» نقشش برایش باز می‌شود: دوره، درس، تکلیف میدانی، کلاس و پخش زنده. «راهیار»ها کنشگران منطقهٔ خودشان را همراهی می‌کنند و «برگزارکننده»ها (بنیادها، مؤسسه‌ها، هیئت‌ها) دوره و مسیر و پخش زنده می‌سازند. ستاد همه را می‌بیند.

- سایت: https://madresehedayat.ir — نسخهٔ در حال اجرا: https://madresehedayat.ir/api/health
- کلاس زنده: https://live.madresehedayat.ir (BigBlueButton روی همان سرور)
- صاحب کار: **معین محمدی**. سرور: **محمدجواد داودی (جواد)**.

## دسترسی‌هایی که همکار تازه لازم دارد

1. **گیت‌هاب:** عضو `cando-hq` با دسترسی نوشتن به `madresehedayat` (و `c-test` برای بایگانی). در claude.ai: «Connect GitHub».
2. **پروژهٔ «مسجد» در claude.ai** (اسناد و گفت‌وگوها) — معین اضافه می‌کند.
3. **پنل بارگذار** (بایگانی) — معین اضافه می‌کند.
4. **سرور:** دسترسی مستقیم لازم نیست؛ هر کار سرور را با دستور دقیق و کامل به جواد بده.
5. **کانکتور روزنگار** برای فرستادن پیام به جواد و نیما.

## چرخهٔ کار: از تغییر تا روی سایت (بی‌نصب دستی)

1. کد را عوض کن و آزمون بنویس.
2. نسخه را بالا ببر: `"version"` در `apps/api/package.json` و `apps/web/package.json`، و یک بخش `## X.Y.Z — تاریخ شمسی` بالای `CHANGELOG.md` (فارسی، به زبان کاربر).
3. آزمون‌ها (محلی، هرگز روی سرور):
   ```bash
   cd apps/api && npm run build && cd ../..
   bash tests/audit/stack.sh fresh
   TEST_DB='postgresql://postgres@localhost:5433/madrese_test?host=/tmp/pg' API_URL=http://localhost:3100/api WEB_URL=http://localhost:5180 python3 tests/run.py --ui
   ```
   «همه درست» باید بیاید. `01_network` در اجرای دوم پشت‌سرهم خطا می‌دهد؛ همیشه روی پایگاه تازه (`fresh`) اجرا کن.
4. `git commit` و `git fetch && git rebase origin/main && git push origin main`.
5. سرور هر ۳ دقیقه گیت‌هاب را نگاه می‌کند (`deploy/auto-update.sh`): پشتیبان پایگاه داده ← کد تازه ← `docker compose up -d --build` (که مهاجرت‌ها و `seed` را اجرا می‌کند) ← چک سلامت ← ساخت وب. اگر بالا نیاید، خودش برمی‌گردد.
6. چند دقیقه بعد `/api/health` باید نسخهٔ تازه را بگوید.
7. **بایگانی را به‌روز کن:** `python3 tools/archive/build.py /path/to/c-test/projects/madrese-archive/site` و در `c-test` commit و push.

## خط‌های قرمز

- دادهٔ واقعی کاربران به هیچ سرویس ابری یا هوش مصنوعی بیرونی نمی‌رود (پیامک و بله و نشان فقط همان کاری که لازم است).
- رمز و توکن هیچ‌جا جز `.env` سرور. اگر کسی در چت فرستاد، استفاده نکن و بگو باطلش کند.
- فونت **رواق** مجوز خریدار دارد؛ جای عمومی منتشر نشود.
- `tests/` هرگز روی سرور اجرا نشود.
- `docs/sources/` اسناد محرمانه دارد (از جمله نامه‌ها)؛ فقط برای زمینه.
- مهاجرت پایگاه داده دستی نوشته می‌شود (`apps/api/drizzle/NNNN_*.sql` و `meta/_journal.json`) و باید سازگار رو به جلو باشد.
