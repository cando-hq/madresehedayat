# راه‌اندازی سرور مدرسهٔ هدایت

۶ آبان ۱۴۰۵

هدف این مرحله: داشبورد ستاد روی دامنهٔ واقعی بالا بیاید تا پشتیبانی دوره‌ها را بارگذاری کند. کل کار با Docker Compose است و حدود نیم روز زمان می‌برد.

| --- | --- | --- |
| ۰ | آماده‌سازی: دامنه، سرور اصلی، دسترسی مخزن، فونت، شمارهٔ مدیران | همین حالا |

## پیش از شروع

| مورد | حداقل برای شروع | توضیح |
| --- | --- | --- |
| سرور | ۴ هسته، ۸ گیگ رم، ۱۰۰ گیگ SSD، Ubuntu 22.04 یا 24.04 | داخل کشور. ویدیوها از آپارات پخش می‌شوند، پس دیسک زیاد لازم نیست |
| نرم‌افزار | Docker و Docker Compose v2، git | همهٔ اجزا (پایگاه داده، فایل‌ها، API، وب، پشتیبان) داخل کانتینر است |

| مخزن کد | github.com/shahcheshme70-cando/madresehedayat، شاخهٔ main | پیشنهاد: اول مخزن خصوصی شود و به تیم فنی دسترسی داده شود |

| شمارهٔ مدیران ستاد | شمارهٔ همراه کارفرما و مسئول پشتیبانی | این شماره‌ها با اولین ورود «مدیر ستاد» می‌شوند |

## مرحله‌های راه‌اندازی

1. کلون مخزن:

```bash
git clone https://github.com/shahcheshme70-cando/madresehedayat.git
cd madresehedayat
```

2. فونت‌ها: پنج فایل `RavaghFaNum-*.woff` را در `apps/web/public/fonts/` بگذارید. اگر نباشند، سامانه با فونت وزیرمتن بالا می‌آید.
3. تنظیمات: `cp .env.example .env` و مقدارها را طبق بخش بعد پر کنید.
4. اگر Docker Hub یا npm از سرور در دسترس نیست: خط‌های `NODE_IMAGE`، `NGINX_IMAGE`، `POSTGRES_IMAGE`، `MINIO_IMAGE` و `NPM_REGISTRY` در انتهای `.env` را با آینهٔ داخلی فعال کنید.
5. ساخت و اجرا:

```bash
docker compose up -d --build
docker compose ps          # همه باید healthy یا running باشند
curl -s localhost:8080/api/health
```

مهاجرت پایگاه داده و دادهٔ پایه (استان‌ها، شهرستان‌ها، شبکه‌ها) هنگام بالا آمدن API خودکار انجام می‌شود.

6. HTTPS: یک nginx یا Caddy روی همان سرور، دامنه را به `127.0.0.1:8080` بفرستد. نمونهٔ nginx:

```nginx
server {
  listen 443 ssl http2;
  server_name madresehedayat.ir;
  ssl_certificate     /etc/letsencrypt/live/madresehedayat.ir/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/madresehedayat.ir/privkey.pem;
  client_max_body_size 520m;   # بارگذاری فایل صوتی و پیوست تا ۵۰۰ مگ
  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto https;
    proxy_read_timeout 300s;
  }
}
```

7. دیوارهٔ آتش: فقط پورت‌های ۲۲، ۸۰ و ۴۴۳ از بیرون باز باشد. پورت ۸۰۸۰ فقط از داخل سرور.

## تنظیمات فایل .env

رمزها را با `openssl rand -hex 32` بسازید. فایل `.env` هرگز در گیت نرود.

| کلید | مقدار برای شروع | توضیح |
| --- | --- | --- |
| `POSTGRES_PASSWORD`، `JWT_SECRET`، `OTP_SECRET`، `MINIO_SECRET_KEY` | رمز تصادفی | هر کدام جدا |
| `DATA_KEY` | خروجی `openssl rand -base64 32` | **مهم‌ترین کلید.** شماره‌ها، گزارش‌ها و پیام‌ها با آن رمزگذاری می‌شوند. گم شود = آن داده‌ها از دست می‌رود. یک نسخه بیرون از سرور و امن نگه دارید و بعد از راه‌اندازی عوضش نکنید |
| `PUBLIC_URL` | `https://دامنهٔ واقعی` | برای پیوندهای دعوت و اعلان‌ها |
| `COOKIE_SECURE` | `true` | پشت HTTPS |
| `BOOTSTRAP_ADMIN_MOBILES` | شماره‌های مدیران ستاد، با ویرگول | مثلاً `09121234567,09351234567` |
| `SEED_DEMO` | `false` | دوره‌های نمونه روی سرور واقعی ساخته نشود |
| `SMS_PROVIDER` | `console` (تا کاوه‌نگار آماده شود) | کد ورود در `docker compose logs api` نوشته می‌شود |
| `STAFF_MFA` | `on` | کارکنان ستاد باید رمز دوم بسازند |
| `BACKUP_KEEP_DAYS` | `7` | پشتیبان شبانهٔ پایگاه داده روی همان سرور |
| `WEB_PORT` | `8080` | پورت داخلی، پشت nginx |
| بله، ایتا، BBB، کاوه‌نگار | خالی | برای شروع لازم نیستند؛ بخش آخر |

## بررسی و تحویل به پشتیبانی

بعد از بالا آمدن، این چند مورد را تیک بزنید و بعد پیوند را به پشتیبانی بدهید:

- [ ] صفحهٔ اصلی روی دامنه با قفل HTTPS باز می‌شود
- [ ] ورود با شمارهٔ مدیر ستاد: کد از `docker compose logs api | grep 'کد ورود'` یا پیامک
- [ ] ساخت رمز دوم با Google Authenticator و باز شدن «پنل ستاد»
- [ ] ساخت یک دورهٔ آزمایشی، یک درس متنی و بارگذاری یک فایل صوتی (برای آزمون MinIO و سقف حجم)
- [ ] یک درس ویدیویی با شناسهٔ آپارات پخش می‌شود
- [ ] پاک کردن دورهٔ آزمایشی
- [ ] به همکاران پشتیبانی از «کاربران و نقش‌ها» نقش «اپراتور ستاد» داده شد (اول خودشان یک بار وارد شوند)

کار پشتیبانی از این‌جا: «پنل ستاد ← دوره‌ها»، ساخت دوره، فصل و درس، و انتشار. اگر چیزی کم باشد، سامانه هنگام انتشار دقیق می‌گوید چه چیزی. ویدیوها با شناسهٔ آپارات، صوت و پیوست با بارگذاری مستقیم.

## نگه‌داری

- **پشتیبان:** سرویس `backup` هر شب یک نسخهٔ پایگاه داده در volume با نام `backups` نگه می‌دارد. هر روز آخرینش را به جایی بیرون از سرور بفرستید؛ فایل‌های بارگذاری‌شده در volume با نام `files` هستند و آن‌ها هم پشتیبان می‌خواهند. یک بار برگرداندن پشتیبان را روی یک سرور دیگر امتحان کنید.
- **به‌روزرسانی:** `git pull && docker compose up -d --build`. مهاجرت‌های پایگاه داده خودکار اعمال می‌شوند. پیش از هر به‌روزرسانی یک پشتیبان دستی بگیرید.
- **گزارش خطای کاربر:** هر خطای سرور یک «کد پیگیری» ۸ حرفی به کاربر نشان می‌دهد. جزئیاتش: `docker compose logs api | grep <کد>`.
- **آزمون‌ها:** پوشهٔ `tests/` آزمون‌های خودکار دارد؛ طرز اجرا در `tests/README.md`. **فقط روی سرور آزمایشی**؛ آزمون‌ها داده پاک می‌کنند.
- **حریم داده:** دادهٔ واقعی کاربران (شماره، گزارش، پیام، بازخورد) هرگز به سرویس ابری یا هوش مصنوعی بیرونی فرستاده نشود.

## کلاس زنده: نصب BigBlueButton

نسخهٔ پایدار فعلی BigBlueButton ۳٫۰ است (۴٫۰ هنوز آزمایشی است). مدرسه فقط از API آن استفاده می‌کند؛ اتاق‌ها، حضور و ضبط‌ها را خود مدرسه مدیریت می‌کند و Greenlight لازم نیست.

| مورد | حداقل |
| --- | --- |
| سرور | جدا از سرور اصلی، داخل کشور، Ubuntu 22.04 ۶۴ بیتی تازه |
| پردازنده و حافظه | ۸ هسته، ۱۶ گیگ رم با swap |
| دیسک | ۵۰۰ گیگ (برای ضبط‌ها)؛ بدون ضبط ۵۰ گیگ |
| پهنای باند | ۲۵۰ مگابیت متقارن |
| نشانی | IP عمومی و یک زیردامنه مثل `bbb.madresehedayat.ir` |
| پورت‌ها | TCP ۲۲، ۸۰، ۴۴۳ و UDP ۱۶۳۸۴ تا ۳۲۷۶۸ (در دیوارهٔ آتش دیتاسنتر هم) |

1. رکورد DNS: `bbb.madresehedayat.ir` به IP سرور BBB.
2. زبان سیستم باید `en_US.UTF-8` باشد:

```bash
sudo locale-gen en_US.UTF-8 && sudo update-locale LANG=en_US.UTF-8
```

3. نصب با اسکریپت رسمی (دامنه و ایمیل را عوض کنید؛ `-w` دیوارهٔ آتش را هم تنظیم می‌کند، `-e` برای گواهی HTTPS است):

```bash
wget -qO- https://raw.githubusercontent.com/bigbluebutton/bbb-install/v3.0.x-release/bbb-install.sh \
  | sudo bash -s -- -w -v jammy-300 -s bbb.madresehedayat.ir -e admin@madresehedayat.ir
```

4. بررسی سلامت:

```bash
sudo bbb-conf --check
sudo bbb-conf --status
```

5. گرفتن نشانی و رمز API:

```bash
sudo bbb-conf --secret
```

6. در `.env` سرور اصلی بگذارید و API را دوباره بالا بیاورید (`docker compose up -d`):

```bash
BBB_URL=https://bbb.madresehedayat.ir/bigbluebutton/api
BBB_SECRET=<همان Secret که bbb-conf نشان داد>
BBB_CHECKSUM=sha256
```

7. آزمون از داخل مدرسه:

- [ ] در «برنامه‌ها» یک برنامهٔ آنلاین بسازید؛ گزینهٔ «کلاس روی سرور مدرسه» باید دیده شود
- [ ] با یک حساب دیگر ثبت‌نام کنید؛ از ۱۵ دقیقه پیش از شروع «ورود به کلاس» باز می‌شود
- [ ] برگزارکننده از صفحهٔ برنامه با «ورود به کلاس (برگزارکننده)» با دسترسی مدیر وارد می‌شود
- [ ] از گوشی با اینترنت همراه هم صدا و تصویر می‌رسد (اگر نه، سرور TURN بخش بعد)
- [ ] ۵ دقیقه بعد از پایان، ستون «دقیقهٔ حضور» در «مدیریت این برنامه» پر می‌شود
- [ ] اگر ضبط روشن بود، بعد از پردازش (معمولاً تا چند ساعت) «دیدن ضبط» در صفحهٔ برنامه می‌آید

ضبط‌ها را خود مدرسه بعد از ۶ ماه از سرور BBB پاک می‌کند؛ فقط پر شدن دیسک را پایش کنید. اگر سرور به GitHub یا مخزن بسته‌های BigBlueButton دسترسی ندارد، نصب در دانلود گیر می‌کند و برای همان چند دقیقه راه دسترسی موقت لازم است.

## سرور TURN (برای اینترنت همراه)

کاربرانی که پشت اینترنت همراه یا شبکهٔ اداری هستند، بدون TURN ممکن است وارد کلاس شوند ولی صدا و تصویر نگیرند.

1. یک سرور کوچک جدا (۲ هسته کافی است)، Ubuntu 22.04، زیردامنهٔ `turn.madresehedayat.ir`.
2. پورت‌ها: TCP/UDP ۳۴۷۸، TCP ۸۰، TCP/UDP ۴۴۳، UDP ۳۲۷۶۹ تا ۶۵۵۳۵.
3. نصب (یک رمز تصادفی ۸ تا ۱۶ نویسه‌ای بسازید):

```bash
wget -qO- https://raw.githubusercontent.com/bigbluebutton/bbb-install/v3.0.x-release/bbb-install.sh \
  | sudo bash -s -- -c turn.madresehedayat.ir:<رمز> -e admin@madresehedayat.ir
```

4. روی سرور BBB همان دستور نصب مرحلهٔ ۳ را دوباره بزنید و `-c turn.madresehedayat.ir:<رمز>` را به آخرش اضافه کنید.

## پیامک، بله و ایتا

| کار | چه می‌خواهد | کلیدهای .env |
| --- | --- | --- |
| پیامک واقعی | حساب کاوه‌نگار و یک قالب تأییدشدهٔ کد ورود با یک توکن | `SMS_PROVIDER=kavenegar`، `KAVENEGAR_API_KEY`، `KAVENEGAR_OTP_TEMPLATE` |
| اعلان و کد ورود در بله | ساخت بات از @botfather بله | `BALE_BOT_TOKEN`، `BALE_BOT_USERNAME` |
| برنامهٔ ایتا | ثبت برنامه در ایتایار با نشانی `https://دامنه/?eitaa=1` | `EITAA_APP_TOKEN`، `EITAA_APP_URL` |

بعد از هر تغییر `.env`: `docker compose up -d` تا API دوباره بالا بیاید.
